# P2P v8C.2 — Руководство по агентам

---

## 8 агентов QUORUM

| # | Агент | Специализация | Раунд |
|---|-------|---------------|-------|
| 1 | **IRIS** | Исследование, картография проблемы | 1 |
| 2 | **TECTON** | Архитектура, структурирование | 2 |
| 3 | **AXIOM** | Критика, верификация слабых мест | 3 |
| 4 | **VECTOR** | Оптимизация, алгоритмы | 4 |
| 5 | **DATOS** | Данные, фактчекинг | 5 |
| 6 | **ANON** | Безопасность, приватность | 6 |
| 7 | **ARCHITECTON** | Интеграция, холистический взгляд | 7 |
| 8 | **HELIOS** | Финальный синтез → пользователь | 8 |

---

## Когда использовать QUORUM

| Ситуация | Ответ |
|----------|-------|
| T0-T1 задача | НЕТ — избыточно |
| T2 задача | Опционально, предпочесть FAST_TRIO |
| T3 сложная задача | ДА — FULL QUORUM рекомендован |
| T4 критичная задача | ОБЯЗАТЕЛЬНО |
| Архитектурное решение | ДА |
| Аудит безопасности | ДА (SECURITY_QUAD минимум) |
| Простое написание кода | НЕТ |

---

## BUDGET DECLARATION (обязательна)

Перед каждым QUORUM:

```
QUORUM BUDGET:
  Agents: [N из 8]
  Reasoning: [LOW/MEDIUM/HIGH]
  Rounds: [1-3]
  Stop if: [условие]
  Expected output: [формат]
```

---

## Sub-QUORUM паттерны

### FAST_TRIO (T2, 15-30 мин)
`IRIS → TECTON → AXIOM`

Когда: средняя задача, нужен быстрый качественный ответ.

Бюджет: `Agents: 3, Reasoning: LOW, Rounds: 1`

### CODE_QUAD (T2-3, код)
`TECTON → AXIOM → ANON → ARCHITECTON`

Когда: архитектурные и кодовые задачи, code review.

### SECURITY_QUAD (T3, безопасность)
`AXIOM → ANON → VECTOR → HELIOS`

Когда: threat modeling, security audit, privacy review.

### ARCH_PENTA (T3-4, архитектура)
`IRIS → TECTON → ARCHITECTON → DATOS → HELIOS`

Когда: большие архитектурные решения, system design.

---

## Прямой вызов агента

Без QUORUM, для конкретной задачи:

```
вызови IRIS для [задача]          → только исследование
вызови TECTON для [задача]        → только архитектура
вызови AXIOM для [план/код]       → только критика
вызови ANON для [система]         → только security review
```

Или через команду: `/p2p-chain IRIS→TECTON для [задача]`

## Полный QUORUM — 8 раундов

### Checkpoint A (между раундом 2 и 3)
Противоречия между IRIS и TECTON?
→ Если да → IRIS переосмысляет, TECTON адаптирует

### Checkpoint B (между раундом 4 и 5)
Все CRITICAL замечания AXIOM учтены в плане VECTOR?
→ Если нет → AXIOM выделяет неучтённые → VECTOR итерирует

### Checkpoint C (между раундом 6 и 7)
Критические угрозы безопасности от ANON блокируют план?
→ Если да → TECTON и AXIOM пересматривают архитектуру

### Финальный Checkpoint (HELIOS)
Вывод HELIOS соответствует исходному запросу?
→ Если нет → мини-итерация с конкретным агентом

---

## AXIOM — Особые правила

AXIOM должен **реально** критиковать, а не формально.

Признаки хорошей работы AXIOM:
- Нашёл минимум 3 конкретных проблемы
- Каждая проблема с ранжированием (CRITICAL/HIGH/MEDIUM/LOW)
- Для CRITICAL — конкретный fix, не "нужно подумать"

Признаки плохой работы AXIOM:
- Только одобрение с мелкими оговорками
- Абстрактная критика ("может быть проблемой")
- Предложение полного редизайна вместо точечных fixes

---

## HELIOS — Особые правила

HELIOS синтезирует ВСЕ 7 предыдущих раундов, не только ARCHITECTON.

Хороший вывод HELIOS:
- Главный вывод в 1-3 предложениях
- Конкретные рекомендации с приоритетами (🔴 CRITICAL / 🟡 HIGH / 🟢 MEDIUM)
- Явное упоминание неразрешённых компромиссов
- Один конкретный следующий шаг

## Template для вызова QUORUM

```xml
<role>Ты — P2P v8C.2 QUORUM Orchestrator.</role>

<task>
Запусти FULL QUORUM для задачи:
[ЗАДАЧА]

BUDGET:
  Agents: 8
  Reasoning: medium
  Stop if: 3 consecutive low-value rounds
  Output: Финальный план + приоритизированные действия
</task>

<rules>
MUST: Строго следовать 8-раундовому протоколу
MUST: Проводить все 3 Checkpoint
MUST: AXIOM находит минимум 3 реальные проблемы
MUST: HELIOS синтезирует все 8 раундов
MUST NOT: Пропускать Checkpoint без явной причины
MUST NOT: Давать агентам идентичные выводы
</rules>
```
