# bb4pda — BB-разметка 4PDA (нейтральная)

Превращает готовый текст в BB-код форума 4pda.to. **Вывод — только BB-код,
без markdown:** ни `#`, ни `**`, ни `- ` в результате быть не должно.

Скилл про механику, а не про украшательство. Оформление гайда-витрины
с фирменной шапкой, эмодзи и слоганами — отдельная задача и отдельный стиль;
здесь по умолчанию **строгий деловой вид**: минимум цвета, минимум символов,
структура задаётся списками и спойлерами.

## Что скилл НЕ решает

Он не определяет, нарушает ли материал правила, и не пишет вердикт по существу —
это `4pda-квалификация` и `предмодератор/`. Сюда приходит уже готовый текст.

## Шаг 1. Определить жанр

От жанра зависит каркас. Пять рабочих:

<жанры>
  <ж имя="ответ в теме">короткий текст, при необходимости цитата собеседника
    и ссылка на пункт правил. Без шапки, без спойлеров, без цвета</ж>
  <ж имя="объявление куратора">заголовок, суть в 3–6 строках, при длинном
    приложении — один спойлер. Цвет только на одном предупреждении, если оно есть</ж>
  <ж имя="раздел шапки">заголовок раздела, список ссылок или пунктов,
    спойлеры по подтемам. Спойлеры склеены (см. §3)</ж>
  <ж имя="цитата с пермалинком">SNAPBACK + quote, текст ответа под цитатой</ж>
  <ж имя="обращение к модератору">по форме из скилла 4pda-жалоба —
    здесь только разметка того, что там составлено</ж>
</жанры>

## Шаг 2. Собрать разметку

Полный официальный перечень тегов и базовые конструкции —
`reference/common_codes.md`.
Заголовки спойлеров, кавычки, вложенность — `reference/edge_cases.md`.

Каркас делового сообщения:

```
[b]Заголовок[/b]

Суть в нескольких строках.

[list]
[*]пункт
[*]пункт
[/list]

[spoiler=Подробности]развёрнутая часть[/spoiler]
```

Цитирование — две штатные заготовки форума:

```
[SNAPBACK]<post_id>[/SNAPBACK] [B]<ник>[/B], 
[quote name="<ник>" date="<дд.мм.гг, чч:мм>" post="<post_id>"]текст цитаты[/quote]
```

Первая — ответ на пост, уходит первой строкой сообщения. Вторая — цитата
фрагмента. Ник, дата и post_id берутся вместе, одной тройкой: они привязаны
к `post_id`, и подставить дату соседнего поста нельзя. Звание участника
(«Старожил», «Ветеран») — не ник, в цитату не идёт.

Пермалинк на сообщение:
`https://4pda.to/forum/index.php?showtopic=<topic>&view=findpost&p=<post_id>`
— адрес берётся из «Сообщение #N» в углу поста, не из адресной строки.

## Шаг 3. Ограничения парсера — нарушать нельзя

1. **`[code]` внутри `[code]` — никогда.** Вложенный code обрывает разбор
   и ломает пост. Один уровень — максимум.
2. **`[code]` внутри тегов заголовка** (`[b][color]…[/color][/b]`) ломает
   структуру: парсер открывает code прямо в заголовке.
3. **Между соседними спойлерами не должно быть пустой строки.** IP.Board
   превращает перенос в пустой тег: пишется `[/spoiler][spoiler=…]` вплотную.
4. **`[img]` — только системные картинки форума** (`//s.4pda.to/…`). Внешние URL
   форум не принимает. В нейтральном оформлении картинки обычно не нужны вовсе.
5. **Форматированный заголовок спойлера — без внешних кавычек.**
   `[spoiler=[color=Red][b]Текст[/b][/color]]` — верно;
   `[spoiler="[color=Red][b]Текст[/b][/color]"]` — форум выведет сырой код.
   Кавычки допустимы только вокруг простого текста заголовка.
6. **Показать BB-тег как пример** — экранировать скобку (`&#91;`) или вынести
   в `[code]`; текст о разметке внутри разметки — главный источник ошибок,
   такой фрагмент перечитывается отдельно.
7. **`[hide]`** скрывает от незарегистрированных, `[hide=N]` — от написавших
   меньше N сообщений. В теме 1109539 это условие публикации по п. 3 правил
   раздела, а не украшение — см. `правила/R-правила-раздела.md`.

## Шаг 4. Self-check перед выдачей

- [ ] Теги парные, вложенность правильная, висячих закрытий нет.
- [ ] Нет `[code]` в `[code]` и в заголовках.
- [ ] Соседние спойлеры склеены, пустых строк между ними нет.
- [ ] Форматированные заголовки спойлеров — без внешних кавычек.
- [ ] `[img]`, если есть, — только системные адреса форума.
- [ ] В выводе нет markdown.
- [ ] Жанр выдержан: деловое сообщение не превратилось в витрину.

Не сошлось — исправить до показа.

## Проверка рендера

Предпросмотр без публикации делается инструментами на машине Master
(`tools\4pda.js`), у облачной сессии их нет. Поэтому спорную конструкцию
не изобретать, а брать из `reference/edge_cases.md` или из живых образцов
`разметка/BB-живые-образцы.md`; если конструкции нет ни там, ни там —
сказать прямо, что рендер не проверен.
