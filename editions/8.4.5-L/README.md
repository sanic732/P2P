## Для кого
Тех, кому важна **экономия токенов** или кто в чате с лимитом контекста. Новичкам — стартовый вариант.

## Чем отличается
Resolver-Gated Lazy Hybrid: всего **4 локальных BOOT-файла (~10K токенов)**, остальной арсенал (11 lazy-чанков) подтягивается **online** с Gist по триггеру через dependency-resolver с проверкой целостности sha256. Тот же арсенал, что в 8H.3, но не монолитом.

## Плюсы и минусы
- ✅ Минимальный след в контексте; работает на любом из 8 хостов; команды `/p2p-download`, `/p2p-verify`.
- ⚠️ **Нужен хост с включённым инструментом веб-доступа** — арсенал живёт на Gist. Полный набор ~57K при `/p2p-download`.

## Требования к хосту
Любой из 8 моделей **с включённым веб-доступом** (Gemini — grounding/поиск · GPT — browsing · Claude — WebFetch · Grok — X/web · Kimi — Agent/web · Qwen/GLM/DeepSeek — провайдерский web-tool).

> **⚠ Первым делом — `/p2p-verify` (пункт 35).** Команда реально дёргает все Gist-URL и сверяет sha256 + EOF + размеры.
> Начинай работу только после успешного отчёта; не прошло → включи веб-доступ в настройках хоста и повтори.
> Проверено 2026-07-14: claude · gemini · gpt · grok · deepseek · qwen.

## Что нового
Поколение .3: 4-слойная lazy-архитектура (L0 BOOT → L1 RESOLVER → L2 TRANSPORT → L3 GIST), sha256-verify каждого чанка, live specs из unpinned Gist. В 8.4.3: единый режим `GIST_LAZY_FETCH`, BOOT сжат −52%, Live Specs v8.6.3, плагинная форма удалена.

## Установка
4 BOOT-файла из `boot/` в контекст → выбрать хост → `/p2p-verify` → `СТАРТ`. ZIP-ассет: `p2p-light-8L.3.zip`. Подробно — `INSTALL.md`.

> ⚠️ Не смешивайте файлы разных редакций — архитектуры синтаксически несовместимы.
