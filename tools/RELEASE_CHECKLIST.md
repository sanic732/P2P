## Один заслон вместо тринадцати галочек

```
python tools/release_gate.py --release <каталог со собранными ассетами>
```

Каталог — **параметр**, не литерал: он меняется от версии к версии, и путь,
прибитый к номеру, рвётся при подъёме без единого слова (на 8.4.7 — трижды
за один заход). Версия выводится из имён ассетов, эталонный тег — из версии.

Заслон печатает у каждой проверки **число осмотренных объектов рядом с числом
провалов** и падает кодом **2** при любом провале, при нуле осмотренных и на
несуществующем пути. Зелёный вывод и код 0 — единственное, что считается
разрешением публиковать.

| Что сторожит | Код | Чем оплачено |
|---|---|---|
| мишень существует и не пуста | G01 | `claude plugin validate` на несуществующем пути выходит кодом 0 |
| пять тел поставки на месте | G02 | тел ПЯТЬ, а не восемь: 4 редакции + вторая форма C |
| состав архива = состав тега | G03 | ассет, собранный по дереву, тянет untracked: 330 КБ → 23 МБ |
| внутри поставки нет мусора сборки | G04 | `EXCLUDE` в `pack_release.py` сверялся через `endswith("pack.")` и не срабатывал никогда — `pack.ps1`/`pack.sh` уезжали внутрь плагина каждый выпуск (починено 10.09) |
| пути forward-slash | G05 | `Compress-Archive` пишет backslash, часть распаковщиков ломается |
| содержимое = источник, **по тексту** | G06 | побайтно краснело 44 файла из 47 при нулевом расхождении (CRLF в git, LF в сборке) |
| эталон — **тег**, тег слит в main | G07 | 8.4.7-C воспроизводился только из коммита на ДВА позже тега |
| версия внутри ассета | G08 | Claude Code кэширует по версии: та же версия — апдейт не перекачивает |
| версия в **заголовке** README и во frontmatter | G09 | на 8.4.7 неверна в 8 файлах из 8 при верной строке «**Версия:**» |
| YAML-шапки загружаемых объектов плагина | G10 | `commands/p2p.md` не парсится, `/p2p` грузится с пустыми метаданными — **в опубликованном плагине** |

| заслон не уехал внутрь поставки | G14 | ровно так уехал `pack.ps1` |
| концы строк внутри ассета — **LF** | G15 | перезалив 8.4.7-L 10.09 с CRLF сломал загрузку Lite на хосте Qwen: `\r` в хвосте url индекса. G06 сравнивает по тексту с нормализацией и этот дефект НЕ ВИДИТ |

Заслон проверяется парой:

```
python tools/release_gate_blind.py
```

Она строит свой репозиторий во временном каталоге, ломает его по одному месту
и убеждается, что заслон **назвал имя** — «провалов 1» без имени файла починить
не даёт. Отдельно проверяет обратное: здоровый выпуск проходит на код 0, а
законное (упоминание `-latest` в чейнджлоге) не краснеет. Итог — строка
«мутаций N, замечено N»; расхождение роняет код 2.

**Пару прогонять после любой правки заслона.** Она уже нашла в нём мёртвую
проверку: `zipfile` под Windows превращает backslash в слэш и при записи,
и при чтении, поэтому G05 в первой редакции не могла сработать никогда,
оставаясь зелёной. Теперь имена читаются разбором центрального каталога zip.

## Порядок выпуска

Решение зоны: **эталон — тег**. Ассет, собранный не из тега, не воспроизводится
и не проверяется — в 8.4.7 C-пара собралась из коммита на два позже тега, и
узналось это только пересборкой из 21 коммита подряд.

```
1. правки          → ветка, коммиты
2. модули на гист  → python tools/verify_gist_live.py  (0 расхождений)
3. слито в main    → PR, squash-merge
4. тег             → git tag v<версия>   (ПОСЛЕ слияния)
5. сборка ИЗ ТЕГА  → python tools/pack_release.py --out <каталог>
6. КАРАНТИН        → python tools/release_gate.py --release <каталог>   ← код 0 или стоп
7. публикация      → только по явному «да» автора
8. после заливки   → скачать ассет обратно и прогнать карантин на скачанном
```

Шаг 8 не формальность: проверяется не то, что собрано, а то, что доехало.
Заслон одинаково работает и по локальному каталогу, и по каталогу со скачанными
ассетами — путь параметр, а состав и содержимое берутся **из тега**, а не из
рабочего дерева. Это не мелочь: дерево уже переименовано под следующую версию,
и сверка с ним покраснела бы на всех 242 файлах, ничего при этом не сообщив.

**Проверено на прошлом выпуске.** Прогон по четырём ассетам 8.4.7 с `--tag v8.4.7`
дал ровно то, что было измерено вручную за день до появления заслона: состав пяти
тел до файла (C for-chat 48 · C plugin 83 · H 47 · N 36 · L 15 · уровня `8.4.7-C` 10),
239 файлов совпали с тегом **по тексту** (побайтно там расходились 44/33/10 файлов
одними переводами строк), 8 провалов на 12 README, 14 файлов с алиасами `-latest`,
`pack.ps1` и `pack.sh` внутри поставки. Заслон, который не проверен на данных,
где ответ известен заранее, — это ещё не заслон.

**Порядок «гист раньше main» менять нельзя.** В 8.4.7 его выполнили наоборот,
и редакция Lite полтора месяца грузила модули 8.4.6.

## Чего заслон НЕ проверяет

Пишется здесь, чтобы зелёный вывод не читался как «проверено всё».

- **Смысл текстов.** Что написано в редакциях — решение автора, не машины.
- **Актуальность фактов о чужих моделях.** Это `audit_model_data.py` (внутренний);
  он по имени исключает `live_specs.md` — четыре копии по 61 КБ, главный
  носитель таких фактов. Дыра известна, не закрыта.
- **Связность ссылок внутри редакций.** Это `verify_links.py`, и он докладывает
  висячую ссылку, только если та начинается с `!`: найдено 18, доложено 0.
  Не чинилось.
- **Состояние гиста.** Это `verify_gist_live.py`, шаг 2.
- **Совпадение forms C между собой** (`for-chat` ↔ `plugin`). Сверка 04.09.2026:
  12 совпадений и 18 расхождений, `for-chat` новее. Отдельного инструмента нет.
- **YAML-шапки ВНЕ плагина.** G10 разбирает только то, что лежит в `*.plugin`.
  Замер 10.09.2026 по остальным телам: в `8.4.8-C/for-chat` не парсится **25 шапок
  из 44**, в редакции H — **2 из 37**; в N и L сломанных нет. На загрузку это
  не влияет (их читает не хост, а человек и модель), но метаданные там мёртвые.
  Заведено отдельной работой, в этот выпуск не входит.
